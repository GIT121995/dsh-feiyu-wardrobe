# 2.5D runtime 接入说明（v2.0.0 · 2.5D-only）

> 自 v2.0.0 起换装间**只有 2.5D 渲染这一条可见路径**：DOM 分层纸娃娃（v6/v7 的 `drawOrder`/`layers`/B1-lite 脸部补丁）、
> 双模式开关（`config.dressUp.render` / `?render=`）、`render-config.json` 端点、静态兜底图均已删除（用户拍板的高风险方案 B）。
> v1.0.0 的双模式实现见 git 历史（`feat/2.5d-runtime` 分支 / v1.0.0 tag）。

## 1. 行为与开关

| 场景 | 行为 |
|---|---|
| 浏览器支持 WebGL2 | 进入换装间即启动 2.5D runtime（按需加载当前身形 rig + 图集）；无可切换的「DOM 模式」 |
| 浏览器不支持 WebGL2 / context lost（永久失败的 context） | **只显示纯文本提示 + 重试按钮**（「当前浏览器/设备不支持 WebGL2，换装间需要 WebGL2；请升级浏览器或开启硬件加速（GPU 渲染）」）；**不做静态图/人物兜底**，不保留第二套渲染 |
| `prefers-reduced-motion: reduce` | 关闭随机眨眼/笑眼等自动动画与互动动作曲线（画面仍静态渲染；互动台词/HUD 正常） |
| 宿主互动开关 | `config.dressUp.interaction.enabled`（默认 `true`）→ `client-config.json` 下发 interaction 端点；关闭/静态托管 → 页面 local-only（只播台词/动作，不扣鱼粮） |

页面 boot 不再读任何渲染配置；`client-config.json` 只含 `{version:4, interaction:{...}, assets:{...}}`（v3.2.0 起版本 4，assets 清单含 rig.bin + 懒加载图集页）。

## 2. 资产与加载

```
docs/dress-up/art/2d5/<shape>/
├── rig.json        # 紧凑 rig（工具/QA/JSON 回退用；v3.0 paper-doll：65 骨、chibi 48 / girl 49 drawables）
├── rig.bin         # 运行时实际加载的二进制 rig（feiyu-rig-binary v1，flat-f32 typed array；≈0.96MiB raw）
├── rig.bin.br      # 构建期 brotli q11 预压缩产物（首屏传输 ≈133KiB；静态服务器直接发 br）
├── atlas.webp      # lazy 第 0 页 = base 页（身体/头发/脸/尾巴等常驻层；chibi 2578×906 ≈659KiB / girl 2824×852 ≈529KiB）
├── atlas-2.webp    # 套装页 maid（该套 2 个整层 drawable）
├── atlas-3.webp    # 套装页 hoodie-plaid
├── atlas-4.webp    # 套装页 hoodie-pleated
├── atlas-5.webp    # 套装页 sailor-plaid
└── build-report.json
```

`<shape>-hi/` 同构：base 页 = 2x 主体/发/脸/tail + 常驻 1x `seam-fill`，4 个套装页 = 1x 整层服装。

- **lazy outfit page（v3.2.0 方案 C）**：首屏只加载 `rig.bin` + base 页 + **当前造型所需套装页**
  （默认 maid ⇒ 共 2 页图集）；首帧后 ≈220ms 空闲预取其余 3 页。切装命中未加载页时 `setLook` 保留旧造型、
  后台补页完成后自动应用（不裸身/不闪错套装）；`setShape(shape, {look})` 可传首帧期望造型。
- **rig 二进化（v3.2.0）**：`rig.bin` = header JSON（rig 元数据 + meshMeta）+ 扁平 typed array 段
  （positions/uvs/weights/deform Float32Array、bones/indices Uint16Array），运行时零拷贝解码
  （≈0.6–0.8ms vs `JSON.parse` ≈24–29ms）；`rig.bin` 404/解码失败自动回退 `rig.json`
  （`toRuntimeRig` 归一成同一扁平形状，consumer 只认一种）。格式规范见 `.scratch/p1-320/RIG-BINARY.md`。
- **传输压缩（v3.2.0）**：静态服务器支持 `Accept-Encoding: br`（构建期 `.br` 预压缩优先、缺省 q5 动态压缩、
  gzip 9 回退）；首屏 rig 传输 gzip ≈285KiB → brotli ≈133KiB。
- **资产版本** `?v=25`（app.js `RUNTIME_2D5_ASSET_VERSION` → runtime fetch URL）；页面模块版本 **v28**。
  资产内容变更必须升资产版本（否则浏览器缓存命中旧图）。
- **首屏 payload（lo tier，默认 maid，v3.2.0，headless）**：rig.bin.br ≈133KiB + base 页 ≈659KiB + maid 页 ≈195KiB
  ≈ **0.96MiB**（chibi）；rig ≈125KiB + 529 + 161 ≈ **0.80MiB**（girl）。请求数 = 2 个 JS + 1 rig + 2 图集 = **5**
  （其余 3 个套装页在首帧后空闲预取）。v3.1.1 基线 chibi ≈1.47MiB（单页图集 + gzip rig）。
- **构建（W0-a 起管线入仓，资产可复现）**：
  ```bash
  npm run fetch:sources    # 下载 assets-src-v4.tar.zst（GitHub Release tag assets-v4；sha256/逐文件校验）
  npm run build:assets:v26 # tools/art/build_prod.py --build-atlas --master-config …
                           # → tools/art/dist/{chibi,girl}/（gitignored；中间产物 .cache/build/）
  npm run build:assets:hi  # hi tier（2x base 页 + 1x 套装页）直接写 docs/dress-up/art/2d5/{shape}-hi/
  ```
  `tools/art/build_prod.py` 从源根 `<src>/` 组装 cutout source rig 后调用 `tools/art/build_2d5.py`
  （有界 MaxRects 打包 + UV 重映射 + 定点化 + 逐页 `pixelEqual`/UV/引用完整性校验 + `rig.bin`/`rig.bin.br`
  生成；失败退出码 1，不要手改产物）。构建确定性：同源双跑 `rig.json`/`rig.bin`/全部图集页 md5 一致；
  与官方 `docs/dress-up/art/2d5` 逐字节一致（`npm run verify:full` 校验，源缺失时跳过）。
  5 页契约由 `tests/asset-build.test.mjs`/`tests/dressup-2d5-assets.test.mjs` 守住（页序/文件名/每 drawable
  恰好一页/base 页不含 outfit 整层/每套装页恰 2 个整层）。源包布局/命令/已知限制见 `tools/art/README.md`。
- **首屏 preload**：`index.html` 只 preload `rig.bin` + base 页图集（`?v=25`）；套装页由 runtime 懒加载/空闲预取。
- **DIY 参考掩膜**：`art/diy/masks/chibi/{body,hair,arms}.webp` 是 DIY 本地成层算法（fill-under-hair/拆袖）的不可见输入，
  不是渲染资产/人物图层；只有 `docs/dress-up/diy-*.js` 引用。

## 3. runtime API（`docs/dress-up/runtime-2d5.js`）

```js
import { createRuntime2D5 } from './runtime-2d5.js?v=28';
const rt = await createRuntime2D5({ canvas, assetRoot: 'art/2d5/', assetVersion: '25', quality: 'auto', device });
await rt.setShape('chibi', { look: { outfit, top, bottom } });
// ↑ 按需加载 + 激活（v3.2.0 lazy：按 look 只拉 base 页 + 当前套装页；切身形释放旧资源，参数/物理/时间保留）
rt.setLook({ outfit, top, bottom });
// 套装优先；否则上衣+下装动态组合（缺件回退 + warnings）。v3.2.0：若所需套装页尚未加载，
// 会保留旧造型并在后台补页后自动应用（不裸身/不闪错套装）；返回值是当前生效 look。
rt.setParams({ headY: 6, breath: 0.8 }); // 参数总线（见 §4）
rt.setHeadFollow(nx, ny);            // 指针跟随（-1..1；null=回正）
rt.triggerBlink(); rt.triggerSmile(); rt.triggerTalk(1.2); rt.setTalking(true); rt.tap();
rt.setQuality('low'|'medium'|'high'|'auto'); rt.setDPR(1.5); rt.setPhysicsHz(30);
rt.setMaskPass(false); rt.setMipmaps(true); rt.setStatic(true); rt.setAuto(false);
rt.start(); rt.stop(); rt.setPaused(hidden); rt.freeze(true); // 冻结后手动 step/advance 确定性截图
rt.step(1/60); rt.advance(60, 1/60); rt.renderFrame();
rt.renderToCanvas(ctx2d, x, y, w, h);   // 立绘卡合成（当前帧 → 2D canvas）
rt.toDataURL({ width: 184, height: 328 }); // 悬浮鲸鱼小图（透明底 dataURL）
rt.getMemory(); rt.getQuality(); rt.getState(); rt.getAssetInfo(); rt.getTickInfo();
rt.destroy();
```

纯逻辑（画质档/参数钳制/换装组合/可见 drawable/face 状态机/固定步长）在 `runtime-2d5-core.js`，node 单测覆盖。

## 4. 参数总线（M5 互动接口）

`setParams(partial)` 接受键（越界钳制，未知键忽略）：`headX` / `headY` / `headZ`（±25°）、`breath`（0–1）、
`eyeOpen` / `eyeSmile`（0–1）、`mouthOpen`（0–1）、`hairSway` / `skirtSway`（0–1）。
另有临时通道：`setTalking(true)` 口型循环、`triggerBlink/Smile/Talk`、`tap()`（轻点头+笑眼+眨眼）。
参数曲线/动作状态机在 `interaction-model.js`，由 app.js 的 `playAction()` 驱动。

## 5. DIY 静态贴片（v2）

- DIY 本地衣柜逻辑不变（IndexedDB 记录 → 注入 `manifest.items`，`item.layers[shape][slot] = blobURL`）。
- 选中 DIY 条目时：runtime `freeze(true)`（暂停物理/动画）+ canvas 2D overlay 按槽位顺序
  （`bottom → topBody → sleeve`，见 `wardrobe-core.diyLayerUrls`）叠加全画布 675×1200 位图；
  UI 提示「DIY 造型为静态，不支持骨骼动画」；**不允许退回 DOM**。
- 立绘卡/悬浮鲸鱼会把静态帧 + DIY 贴片一起合成；切回非 DIY 条目恢复动态。
- DIY 记录 `shape=chibi`：girl 身形下选中 DIY 条目会提示「DIY 单品只做了 Q 版」并用普通 2.5D 造型。

## 6. 页面接线（`docs/dress-up/app.js`）

- `bootRuntime()`：2.5D 是唯一路径；失败 → `showRuntimeUnavailable()` 只显示文本提示（可重试）。
- `applyState()` → `sync2d5()`（setShape/setLook/DiyStatic/renderFrame）+ 背景/特效/衣柜/立绘卡元信息刷新。
- `say()` → runtime 口型；`pointermove` → head follow；角色点击 → 头部摸头/身体 tap；`saveCard()` → `renderToCanvas` 合成；
  `composePetImage()` → runtime 帧（+ DIY 贴片）→ `toDataURL` 写悬浮鲸鱼小图。
- E2E/调试入口：`window.__feiyu2d5`（ready/runtime/failure/unavailable/retry/getState/getMemory/diyMode/
  diyOverlayVisible/simulateDiy/clearDiy/freeze/setAuto/advance/step/resources）。

## 6.5 cutout 槽位与多图集（v2.2 起已合入 production 资产；v2.6 为素体母版 v3 重贴图资产）

B 方案（Live2D/Spine 式 cutout 素体重制）已落地：**v2.2–v2.7 为 cutout 分件形态**（v2.7.0：65 骨（59 前缀 + 6 legBones，原索引不变）、chibi 69 / girl 70 drawables，单页 pixelEqual）；**v3.0 起由整层 outfit 替代**（chibi 48 / girl 49 drawables，见 §6.6）。
runtime/core 支持 **多图集（≤6 页）**（`rig.atlases` + `drawables[].atlas`；v3.2.0 起 lo/hi 均为 5 页 lazy 布局）；v2.1 旧 rig 与旧 DIY pack 继续兼容。

> 下表为 v2.2–v2.7 cutout 分件槽位语义；v3.0 production rig 已退役这些分件（旧 rig / 旧 DIY pack 兼容路径仍识别）：

| 槽位 | z | 语义 |
|---|---:|---|
| `legs` | 9 | 腿/脚 cutout 部件（先绑 hips，裙子后面） |
| `body` | 10 | 躯干（原 body 槽位语义不变） |
| `armUpper` / `armFore` / `hand` | 45 / 48 / 65 | 上臂 / 前臂 / 手（服装 sleeve 之下/上按 z 排） |
| `collar` | 56 | 领/胸饰/围裙等独立层（服装槽位，随 outfit） |
| `sleeveUpper` / `sleeveFore` | 60 / 62 | cutout 袖子分段（手 z65 在袖口外） |

- `BODY_DRAW_SLOTS`：`hairBack/strands/body/legs/arms/armUpper/armFore/hand/hair/hairFront/collar`（来自 `rig.slots` 常驻层）。
- `OUTFIT_SLOTS`：旧 `topUnder/bottom/topBody/sleeve` + 新 `sleeveUpper/sleeveFore/collar`；outfit 可同时给多槽位。v3.0 整层 outfit 只使用 `topBody`/`bottom`，其余槽位为空数组。
- **多图集**：rig 用 `atlases: [{id,file,width,height}, …]`（≤`MAX_ATLASES`=6 张；production 5 张）；每个 drawable
  用 `atlas` 指定 id/下标/文件名，缺省第一张。旧 rig 的 `atlas: {file,width,height}` 单图集继续加载；旧
  `getState().look.slots` 的 4 个键语义不变（cutout 新槽位仅在非空时追加，旧路径字节级不变）。
  v3.2.0 首屏只加载 base 页 + 当前套装页（其余页懒加载；见 §2）。
- `resolveLook` 输出 slots 为 7 键全集；runtime `getState().look.slots` 对旧 rig 仍只返回 4 键。
- **v3.0 造型清单**：production 套装 = `base`（素体）/ `maid`（默认，`rig.defaults.outfit=maid`）/ `hoodie-plaid` / `hoodie-pleated` / `sailor-plaid`（每套 = `{combo}-top` + `{combo}-skirt` 整层，见 §6.6）；衣柜上衣仅 `hoodie` / `sailor`，与下装 `plaid` / `pleated` 动态组合为 `<top>-<bottom>`（命中同一套 `<top>-<bottom>` outfit；`sailor-pleated` 无组合 → `resolveLook` 记 warning 并回退默认套装，不抛错）。旧 v2.1 generic / v2.2–v2.7 分件引用经 `LEGACY_V21_BASE_REFS` / `LEGACY_V22_BASE_REFS` 统一映射到整层 id；旧存档 `top=sweater` / `outfit=sweater-*` 经 `normalizeState` 回退默认。
- DIY 增量 pack 兼容：`topBody/bottom/sleeve/topUnder` 语义不变；新槽位 `sleeveUpper/sleeveFore/collar` 可直接写入 pack，
  旧别名 `arms/arm/sleeves → sleeve` 自动映射；`addOutfitPack/removeOutfitPack` 与多图集 scene 兼容（DIY 纹理独立）。
  旧 pack 的 base 引用迁移按当前 `scene.outfits` 动态 auto-pair：v3 只补 1 个整层（top/skirt），v2.7 分件 rig 保持旧观感；用户自绘层永不丢、同一整层只落一次。
- 校验：`normalizeAtlases`（≤`MAX_ATLASES`、重复 id/缺 file 报错）、`resolveDrawableAtlas`、`collectLookAtlasIndices`（懒加载页选择）；core 单测覆盖。

## 6.6 v3.0 paper-doll 整层服装契约（资产 v25 / 页面 v28；v3.2.0 起叠加 lazy 5 页图集）

- **每套 outfit = 2 个整层 drawable**（替代 v2.2–v2.7 的 6–9 个 cutout 分件，见 PLAN §2/§4）：
  - `{combo}-top`：slot `topBody`、z=**64**（高于 body 手臂 45/48，低于手 65 / hairFront 70）；领口 + 衣身 + 袖 + 领饰一体，单张全画布纹理 + 单网格；
  - `{combo}-skirt`：slot `bottom`、z=**30**（与原 bottom 槽位一致）。
- `rig.outfits[combo] = { name, topBody: ['{combo}-top'], bottom: ['{combo}-skirt'] }`；combo = `maid` / `hoodie-plaid` / `hoodie-pleated` / `sailor-plaid`（另有 `base` 素体）。
- **旧分件退役**：v3 production rig 不再有 `collar` / `sleeve` / `sleeveUpper` / `sleeveFore` / `topUnder` 的 drawable；`resolveLook` / `visibleDrawables` 按「缺省空数组」处理这些槽位，不假设分件必填，`getState().look.slots` 的旧 4 键语义不变。
- **兼容映射**：旧 v2.1 generic 引用（`hoodie-body`/`sweater-body`/`bottom-plaid`…）走 `LEGACY_V21_BASE_REFS`，v2.2–v2.7 分件引用（`*-torso`/`*-collar`/`*-sleeve-upper|fore`/`*-skirt-under`）走 `LEGACY_V22_BASE_REFS`，统一收敛到 `{combo}-top` / `{combo}-skirt`（同层去重、不重复叠加 base 服装）；目标缺失记 unmapped 不抛错，用户自绘层不丢。旧存档（`top=sweater` / `outfit=sweater-*`）由 `normalizeState` 回退默认，`resolveLook` 对残留未知套装/无组合 top+bottom 回退 rig 默认套装并记 warnings。
- **视觉门禁**：baseline 为 2 身形 × 5 造型 × 7 区域（1x 全身 + 2x 膝/手/肩/脚/腹/发/**颈**）= **80 张**；`tests/garment-hygiene.test.mjs` 校验整层结构 + 烘焙皮肤 = 0 + 非功能性 alpha 孔洞 = 0。

## 7. 已知限制（v2 初版 / v2.2 cutout 补充）

1. **无 WebGL2 用户失去换装间**（用户已接受）：只有文字提示，无静态人物/兜底图。
2. **DIY 为静态贴片**：贴片叠在 2.5D 静态帧最上层，可能盖住个别手臂/发丝细节；无骨骼动画/物理。
3. **真机性能未测**：所有 FPS/CPU/内存为服务器侧 headless（SwANGLE 无 GPU）数据，不可代表真机；不做 60fps 承诺。
4. 背景/特效仍在 DOM/CSS 层（透明 canvas 只画角色）；换背景不触发 canvas 重绘。
5. 历史文档（PLAN-2.5D-RIG / LAYER-MODEL / DIY-UPLOAD 等）已归档到 `docs/archive/`（DOM 时代章节退役，仅作历史参考）。
