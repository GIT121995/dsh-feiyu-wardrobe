# 换装图层叠加 · 技术选型（v0.9.0）

> 触发：用户反馈「图层叠加层次关系还是不对」（v0.8.0 线上）。
> 结论先行：**缺陷根因在「素材分层 + 数据模型」，不在渲染引擎**。
> 选择 **方案 A：DOM + CSS 多槽位纸娃娃 v2（manifest v6）**，继续用本地 `<img>` 叠图，
> 不引入 Canvas/WebGL 引擎、不引入 2D 骨骼/3D。实现契约见 [LAYER-MODEL.md](./LAYER-MODEL.md)。

---

## 1. 问题取证（v0.8 到底哪里不对）

v0.8 的模型是「5 个固定槽位 + 全局 z」：

```
base(0) → 下装(20) → 上装(30) → 头发叠层(100)
```

这套 z 只能表达「一条直线上的先后」，而换装里真实遮挡是**分层夹心**的。
逐项取证（证据见 `.scratch/feiyu-layer-audit/`，对照物为 raw12 里同一素体上生成的单件 look 真值）：

| # | 现象 | 根因 | 严重度 |
|---|------|------|--------|
| 1 | 少女版手/前臂消失：穿裙子后手被裙层整片盖住 | 手在 `base` 里，`bottom` 的 z 更高 → 手永远在裙后；而真值里手在裙前 | P0 |
| 2 | 手臂下方的长发丝在腰线附近突然消失 | `overlay` 只取了「与头部相连」的蓝发连通块，手臂挡断的**下半段发丝块**被 `top_frac>0.45` 规则误杀；衣服层又在头发处挖了洞 → 该处既没衣服也没头发 | P0 |
| 3 | 衣服图层上有未补的「头发洞」（洋红底可见） | 同上：挖洞按旧 overlay 掩膜，overlay 没覆盖的区域补不回来 | P0 |
| 4 | 水手服是「白色连体衣」盖在裙子外 | 素材问题：look/whiteout 生成成了连体式（含白色下装），旧 z 又把整件盖在裙上 | P1 |
| 5 | 少女版卫衣丢了橙色蝴蝶结 | 素材问题：whiteout 无蝴蝶结，配准只取 whiteout alpha | P2 |
| 6 | 长袖袖口与手的先后、短袖前臂与裙的先后无法表达 | 只有单一「上装 z」，装不下「袖在臂上、手在袖外、臂在裙上」三层关系 | P0 |

结论：**无论换成 Canvas、WebGL 还是 2D 骨骼，只要图层还是这 5 张平铺素材，问题 1/2/3/6 依然存在**——
它们不是渲染器算不对，是素材里根本不存在正确的分层信息。

## 2. 候选方案对比

| 维度 | A. DOM+CSS 多槽位纸娃娃 v2（选中） | B. Canvas 2D 单画布合成 | C. WebGL 逐像素深度合成 | D. 2D 骨骼绑定（Live2D/Inochi2D/Spine） | E. 3D（VRM+three.js） |
|---|---|---|---|---|---|
| 修好 1/2/3/6 | ✅ 需要拆部件层 | ✅（同资产下等价） | ✅ 逐像素最彻底 | ✅ 但要重做绑定 | ✅ |
| 改动量 | **中**：build 管线 + manifest + 渲染器槽位 | 中：渲染/导出/鲸鱼小图三条链路重写 | 大：深度图生成 + shader + 回退方案 | 很大：素材绑定/网格/动画，重做全部服装 | 极大：3D 建模、风格重做 |
| 离线/零运行时依赖 | ✅ 纯静态 | ✅ 纯静态 | ✅ 纯静态 | ⚠️ 引擎 runtime + 许可 | ⚠️ three.js + 大体积模型 |
| 性能（v0.8 已优化：点击 <70ms、long task=0） | ✅ 最多 7 张图，仍只更新变化层 | ✅ 合成一次；需重新验证 | ⚠️ GPU/逐像素，低端设备风险 | ✅ 但绑定数据大 | ⚠️ 包体/首帧 |
| 动画/互动扩展（P0 养成） | ✅ CSS 容器动画够用；加动作要另做 | ✅ 可逐帧 | ✅ | ✅✅ 强项 | ✅ |
| 配饰/用户上传衣服扩展 | ✅ 加槽位/加层即可 | ✅ | ✅ | ✅ 但每件都要绑定 | ⚠️ |
| 美术成本 | 低（沿用 Seedream 管线，只加掩膜/拆层） | 低 | 中 | 高（人工绑定） | 极高 |
| 许可/开源合规 | ✅ MIT | ✅ | ✅ | ⚠️ Live2D 商业许可；Inochi2D 生态不成熟 | ✅ |
| 风险 | 掩膜边界 1–2px、素材本身瑕疵 | 中等重构风险、收益为零 | 复杂度/性能回退 | 工期不可控 | 不现实 |

**为什么换渲染引擎不解决问题**：A/B/C 三者渲染的都是同一批 RGBA 图；遮不遮住取决于「图怎么分、按什么顺序叠」。
把 5 张图原封不动丢给 Canvas/WebGL，手依旧会消失。**正确的修复是改分层数据和素材拆法，而不是换画布。**

**为什么也不上 2D 骨骼**：骨骼引擎的强项是动作/表情，不是静态遮挡；而它要求每件衣服重新做网格绑定，
和维护成本相比收益太早。v6 的「部件层 + 槽位」模型和未来骨骼迁移兼容（层=部件约束），以后要做动作再接不迟。

## 3. 选型结论

**采用方案 A**，并在数据模型上补三件事：

1. **身体部件层**：每个身形拆出 `body`（底）、`arms`（手臂+手，在衣服之上）、`hair`（完整前发，最上层）。
   —— 解决「手在裙后」「长发丝消失」。
2. **衣服按手臂掩膜拆「身/袖」两片**：`topBody`（或 `topUnder`）在手臂之下，`sleeve` 在手臂之上。
   —— 解决「长袖被手盖」「短袖前臂被裙盖」「袖口/手前后」。
3. **manifest v6 的 `drawOrder` 槽位模型**（7 槽位，数据驱动）：
   `body → topUnder → bottom → topBody → arms → sleeve → hair`。
   —— 解决「固定 z 表达不了夹心」；以后加配饰/手持只是加槽位，不改渲染逻辑。

渲染继续用 DOM + CSS `<img>` 叠图：**零运行时依赖、纯本地离线、包体不变大、v0.8 性能优化全部保留**。
图层数 5→最多 7（同一时间实际渲染 5–6 张），点击路径仍只有「换 src」和一次 layout 缓存命中。

**未来触发切 B/C/D 的条件**（先记录，不现在做）：
- 配饰/手持层数 > 12 或需要逐像素遮挡（半透明布料、动态裙摆、物理飘动）→ 评估 C（WebGL 深度/遮罩）。
- 需要角色动作/表情（养成互动升级）→ 评估 D（优先 Inochi2D / Spine runtime，避开 Live2D 商业许可）。
- 需要实时换装动画/3D 视角 → E 才有意义。

## 4. 迁移与回滚

- 素材：`tools/build_wardrobe.py` 升 v6（掩膜来自 `tools/masks/<shape>/`，可一键重建）；旧 v5 素材由构建脚本清理。
- 前端：`wardrobe-core.js` 的 `resolveLayers` 改为槽位模型；`app.js` 动态槽位；`index.html` 去掉写死图层。
- 回滚：v0.8.0 的 tag/commit（`58beff9`）完整保留，素材在 git 历史里可一键找回；
  npm 旧版本 `0.8.0` 仍可安装，必要时 `pnpm add dsh-feiyu-wardrobe@0.8.0` 回退。
- 发版纪律：`npm run verify` 全绿 + 视觉回测（见 LAYER-MODEL.md §5）才发；升 minor（0.8.0 → 0.9.0）。

## 5. 遗留与风险（诚实记录）

1. **素材先天瑕疵**：水手服 look/whiteout 是连体式（v6 用「下摆塞进裙子」规避视觉问题，彻底修需重出图）；
   少女版卫衣 whiteout 丢蝴蝶结（v6 在 build 中从 look 补橙色像素）。
2. **掩膜精度**：身体部件掩膜由 CV + 人工 QA 生成，边界 1–2px 误差；`arms` 取保守、`sleeve` 膨胀兜底。
3. **hair 与手臂真实前后关系**：凡可见头发都在素体画面上层，v6 用「hair 最上层」近似；
   若个别发丝压手，可再加 `hairBack` 槽位。
4. v6 的验收不只看代码，必须过 14 组合 × 2 身形的视觉回测（LAYER-MODEL.md §5）。

### 仍存在的近似（v0.9.1 可继续打磨）

1. `hair` 永远最上层是契约近似：个别长袖肩侧发缕在真值 look 里本应在衣服后被盖住，现表现为衣服上的
   1–2px 深色发丝（不是洞）。彻底修需拆 `hairBack` 槽位或按 look 做逐件发丝遮挡。
2. 掩膜/配准有 1–2px CV 边界误差；`sleeve` 已做 6px 膨胀 + 手部裁切兜底。
3. 水手服 look/whiteout 本身是连体式（v6 用「下摆塞进裙子」规避视觉问题），彻底修需重新出图。
